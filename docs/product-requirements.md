# 製品の要求・スコープ

## 目的

製品を製作したい利用者が、製作に必要なアイテムとその数量を把握し、調達の計画に利用できるようにする。

調達方法は利用者によって異なる。自分で採集・調達する、購入する、中間素材を製作するなどの選択は利用者が判断する。システムは、その判断の基礎となる構成情報と必要数量を提供する。

## 対象とする利用者・ユースケース

1. 利用者が製作対象の製品（レシピ）を検索・選択する。
2. 必要な完成品の個数を指定する。
3. BOMツリーを参照して構成と必要数量を確認する。
4. 必要に応じて中間素材の製作レシピを選択する。
5. 製作対象をリストへ登録し、複数製品を管理する。
6. 製品ごとに計算した中間素材、末端素材、クリスタルの必要数量を、アイテムごとに集計して確認する。
7. 登録済み製品は詳細表示で必要個数・中間素材のレシピ選択を変更できる。

## 中間素材の製作に関するユースケース

### UC-001: 中間素材を自分で製作する
- **状況**: 完成品に必要な中間素材を利用者が自作する。
- **目的**: 中間素材の製作に必要な下位素材と数量も把握したい。
- **期待動作**: 中間素材の選択レシピからBOMを再帰展開する。
- **対象外**: 自作・購入の調達方法管理。

### UC-002: 同じ中間素材を異なる方法で作る
- **状況**: 同一中間素材に複数レシピがあり、使う素材も異なる場合がある。
- **目的**: 実際に利用する製作方法での必要素材を把握したい。
- **期待動作**: レシピ選択の変更で下位BOMと集計が更新される。

### UC-003: 自分が作れるレシピしか選べない
- **状況**: 利用者によって製作可能なレシピは異なり、ある利用者はレシピ1でしか作れないことがある。
- **目的**: 自分が実際に製作可能な方法で必要素材を確認したい。
- **期待動作**: 初期レシピに固定せず利用者自身が選択できる。
- **対象外**: 習得レシピの自動取得や選択候補の自動制限。

### UC-004: 同一中間素材を完成品によって使い分ける
- **状況**: 複数の完成品、あるいは1つの完成品内の複数箇所に同じ中間素材が必要になる。
- **目的**: 完成品間では製作方法を変えつつ、同じ完成品の中では一貫した方法を使いたい。
- **期待動作**: 登録製品ごとに選択は独立し、同じ登録製品内の同一中間素材では共有する。

この方針に至った理由・代替案は[設計判断](./decisions/intermediate-recipe-selection.md)に記録する。

## 検索・選択・数量変更・リスト管理のユースケース

### UC-005: 製作品を検索し、選択するとBOMを参照できる
- **状況**: 利用者が製作したいアイテムを探している。
- **操作**: 検索Inputへ製品名を入力し、候補からレシピを選択する。
- **期待動作**: 選択したレシピが現在の表示対象となり、そのレシピのBOMツリーが表示される。検索結果からの選択だけでは、製作リストへの登録は行わない。

### UC-006: 選択中の製品の必要数量を変更する
- **状況**: 製作したい完成品の個数が変わった。
- **操作**: 数量Inputに値を指定する、または増減操作を行う。
- **期待動作**: 有効な数量変更が確定したら保存ボタンなしで選択中のBOMと必要素材数量が更新される。すでに登録された製品の編集時には、対象製品の登録状態と全体集計にも反映する。
- **補足**: 入力途中の空欄・不正値の扱いは別途決める。

### UC-007: 選択中のレシピを製作リストへ追加する
- **状況**: BOMを確認した製品を複数製作対象の集計に含めたい。
- **操作**: リスト追加操作を行う。
- **期待動作**: 選択しているレシピIDをキーに、選択した完成品数量と中間素材レシピの状態をフロントエンドで管理する。選択と登録は別操作とする。

### UC-008: アカウント登録なしで製作計画を作る
- **状況**: 利用者が個人的な製作計画を、その場で確認したい。
- **目的**: 認証やサーバーへのリスト保存なしで、製作対象と必要素材を試算する。
- **期待動作**: 検索・レシピ/BOM取得はバックエンドから行い、現在の選択・数量・製作リストの状態管理とBOM集計はフロントエンドで完結する。
- **対象外**: バックエンドへの選択履歴・製作リストの永続保存。ブラウザ再読み込み後の保持方法は未決定。

設計上の責務分担・即時反映の理由は[設計判断](./decisions/frontend-only-craft-state.md)を参照。

## 機能要求

| ID | 要求 |
| --- | --- |
| R-001 | 製品・製作レシピを検索・参照できる |
| R-002 | BOMの親子関係をツリーで確認できる |
| R-003 | 製作対象をレシピID単位でリストに登録・削除できる |
| R-004 | 同じレシピIDはリストに重複登録しない。異なるレシピIDは同じ完成品であっても別登録とする |
| R-005 | 登録済みの完成製品の必要個数を変更できる |
| R-006 | 中間素材・末端素材・クリスタルの必要個数はBOMと選択レシピから自動計算し、利用者による直接編集を認めない |
| R-007 | 中間素材の製作レシピを、登録製品recipeId × 中間素材itemId単位で選べる。同一登録製品内では共有し、登録製品間では独立させる |
| R-008 | 製品ごとに独立してBOMを展開し、中間素材・末端素材・クリスタルをアイテムID単位で合算して表示する |
| R-009 | 有効な完成品数量や使用レシピを確定したとき、保存ボタンを挟まず表示・集計が更新される |
| R-010 | 製品名の検索Inputから候補レシピを選択すると、当該レシピを選択状態としてBOMツリーを表示する |
| R-011 | 検索結果の選択と製作リストへの登録は別操作とする |
| R-012 | 現在の選択状態・数量・製作リスト・中間素材のレシピ選択はフロントエンドで管理し、バックエンドへ永続化しない |

## スコープ上の制約

- 利用者の認証は不要。
- 利用者による製品・BOMデータの書き込み・編集機能は対象外。
- バックエンドは製品・レシピ・BOMの参照APIを提供し、利用者の選択状態、数量、製作リスト、集計結果を永続化しない。
- 調達方法（購入・採集・製作等）の選択や履歴管理は現段階の対象外。
- 製品を横断した共通中間素材の製作回数最適化は行わない。各製品を独立計算してから結果を合算する。
- 「参照のみ」は製品・BOMデータへの永続書き込みがないという意味。利用者が画面上で製作リストやレシピ選択を変更することは含む。

## 設計情報の位置づけ

本書と [製作数量・集計仕様](./bom-calculation-spec.md) は、対話で合意した期待動作を記述する。既存の実装と矛盾する場合、実装を自動的に正しい仕様とはみなさず、差分を確認する。未確定の判断は [未決定事項](./open-questions.md) に記録する。

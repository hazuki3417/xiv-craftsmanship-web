# 製作数量・BOM展開・集計の機能仕様

## 用語と入力

- **完成製品**: 製作リストへ登録する製作対象。
- **必要個数**: 利用者が指定する完成製品の個数。製作回数ではない。
- **完成個数（pieces）**: 対象レシピ1回の製作で得られる個数。
- **必要数（quantity）**: 親アイテムのレシピ1回で消費する子アイテムの個数。
- **中間素材**: 下位の製作レシピを使って展開する部品。
- **末端素材**: 選択された製作経路で下位へ展開しない素材。
- **クリスタル**: BOMの `type=crystal` に該当する消費アイテム。

製作リストの登録キーは **recipeId** とする。同一recipeIdの二重登録を禁止し、別recipeIdは完成製品が同じでも別登録とする。

## 製作回数・必要数量

あるレシピについて：

```text
製作回数 = ceil(必要個数 / 1回の完成個数)
子アイテム必要個数 = 製作回数 × レシピ1回の子アイテム消費数
```

各中間素材について、算出された「子アイテム必要個数」を次の階層の「必要個数」として再帰的に同じ計算を適用する。切り上げはレシピ単位・製作経路単位で行う。レシピの完成個数は正の整数を前提とする。

### 計算例1：完成品の切り上げ

- 完成品Aの必要個数: 5個
- Aの1回の完成個数: 3個
- Aの製作1回あたり素材Mを2個消費

Aの製作回数は `ceil(5/3)=2` 回。Mは4個必要となる。完成品の余剰1個は今回の集計では別の製品へ割り当てない。

### 計算例2：中間素材の切り上げ

- Aを1回製作すると中間素材Xが5個必要
- Xは1回の製作で3個完成し、素材Yを2個消費

Xの製作回数は `ceil(5/3)=2` 回。Yは4個必要となる。Xの必要個数表示は5個であり、製作結果の6個とは区別する。

## 複数製品の集計

1. 製作リストの各登録レシピを**独立して**再帰展開する。
2. 各製品内の各出現箇所で、親から渡された必要個数と選択されたレシピにより数量を計算する。
3. 製品ごとの計算結果を、中間素材・末端素材・クリスタルの区分ごとにアイテムIDで合算する。
4. **合算後に中間素材の製作回数を再計算しない。** 製品をまたいだ製作回数の削減は対象外。

例: AがXを1個、BがXを1個要求し、Xは1回の製作で3個完成してYを5個消費する場合、A由来のYが5個、B由来のYが5個で合計10個とする。中間素材一覧に表示するXの必要個数は合計2個とする。

同じアイテムが複数経路・複数製品に現れた場合も、区分ごとに同一itemIdの数量を足し合わせる。

## 中間素材のレシピ選択

- 中間素材の製作レシピは利用者が変更可能。
- 初期レシピは候補の **recipeId昇順で先頭** を選択する。API応答順には依存しない。
- 選択状態は登録した完成製品ごとに独立する。Aの中間素材Xのレシピ変更はBのXに影響しない。
- 選択した中間素材のレシピを変更すると、その中間素材の下位構成を新しいレシピで再展開し、数量と集計を更新する。
- 選択状態は **(登録完成製品のrecipeId, 中間素材のitemId)** をキーとして管理する。同じ登録製品内で同一itemIdが複数の経路に登場しても選択レシピは共通とする。
- 異なるrecipeIdで登録した完成品間では、同じ中間素材でも異なるレシピを選べる。
- **選択レシピの共有と必要数量の合算は別**。数量の切り上げは既存仕様どおりBOM出現経路ごとに行い、その後に集計する。

## 状態管理と即時反映の契約

- 画面には製品を検索するInputと、選択中の完成品の必要数量を指定するInputがある。
- 検索候補の選択でレシピを選択状態にし、そのレシピのBOMツリーを表示する。**選択と製作リストへの追加は別操作**。
- 数量Inputや増減操作による**有効な数量変更が確定すると**、保存ボタンを使わずBOMツリーと必要数量を再計算・更新する。
- 登録済み製品を編集している場合、その登録製品に対する有効な数量変更・中間素材レシピの変更をフロントエンドの製作リストと全体集計にも反映する。未登録製品をプレビューしているときは、登録済み製品を暗黙に変更しない。
- レシピ検索・BOM取得には既存バックエンドの参照APIを利用するが、選択中のレシピ、数量、リスト登録内容、レシピ選択は**フロントエンド内だけで管理**する。バックエンドにはこれらを保存するAPI・ストレージを要求しない。
- 選択中の製品・数量と登録済み製作リスト（各登録製品の完成品数量と中間素材レシピ選択を含む）はブラウザ内に保存する。**ブラウザ・タブ終了後、同じブラウザで再アクセスしたときも復元する**。短命なReact stateのみ・sessionStorageのみの実装ではこの要件を満たさない。
- 実装方式は`localStorage`等のブラウザ永続ストレージを想定する。永続化するのは利用者の選択情報・入力値などの必要最小限とし、製品/レシピ/BOMの参照元データはバックエンドから取得して展開・集計を再計算する。キャッシュと正本を混同しない。
- 「製作リストをすべて削除する」操作を提供し、実行前に確認ダイアログを表示する。確認時には登録済み製品とそれに紐づく数量・レシピ選択を一括削除し、素材集計とブラウザ永続ストレージへ反映する。キャンセル時は何も変更しない。
- 一括削除によって未登録の検索プレビュー・現在選択中の製品をクリアするかは未決定（[未決定事項](./open-questions.md)）。
- 読み込み時の不正・旧形式データ、参照先レシピの削除・変更、容量上限や利用者によるストレージ削除への対処は未決定（[未決定事項](./open-questions.md)）。
- 無効・入力途中の数値を再計算へ反映する条件は別途判断する。

## 画面操作と表示

- 完成製品を検索・選択し、必要個数を設定して製作リストに登録する。
- 同じrecipeIdを再度登録しても、登録済み行の数量を暗黙に上書き・加算しない。
- 登録済み製品をリストから選択すると、既存の詳細画面で完成品の必要個数と中間素材のレシピを編集できる。
- **中間素材・末端素材・クリスタルの必要個数は読み取り専用**。レコード行の数値Inputでは編集しない。
- 完成品の必要個数の変更、レシピ変更、登録・削除を集計結果に反映する。
- 数量は1以上の整数とする。上限・不正入力時の確定操作は未決定（[未決定事項](./open-questions.md)）。

## 受け入れテスト観点

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| T-001 | Aが3個/回、Mを2個/回消費。Aを5個要求 | Aの製作2回、Mを4個 |
| T-002 | AがXを5個要求。Xが3個/回でYを2個/回消費 | Xの必要個数5個、Yを4個 |
| T-003 | AとBがそれぞれXを1個要求。Xが3個/回でYを5個/回消費 | Xの合計必要個数2個、Yの合計10個 |
| T-004 | 同一recipeIdを2回登録 | 登録行は1件。数量は自動加算・上書きされない |
| T-005 | 同じ製品でrecipeIdが異なる2レシピを登録 | 2件として登録でき、それぞれ独立計算 |
| T-006 | 同一中間素材に複数レシピ | recipeId昇順で初期選択される |
| T-007 | 登録製品Aの中間素材レシピを変更 | Aの下位構成・集計を再計算し、Bの選択は変わらない |
| T-008 | 登録済みAの必要個数を変更・削除 | 対応する必要数量・集計が更新される |
| T-009 | 素材の数量一覧を表示 | 中間・末端・クリスタルの算出数量を直接編集できない |
| T-010 | 同一登録製品のBOMにXが複数回出現 | Xのレシピ選択を全出現箇所で共有し、変更時には全箇所で再計算 |
| T-011 | 異なる登録製品A・Bに中間素材Xがある | AとBで異なるレシピを選択できる |
| T-012 | 同じ製品の2経路でXが1個ずつ必要。Xは3個/回、Yを5個/回消費 | レシピ選択は共有しても経路別に切り上げ、Yの合計は10個 |
| T-013 | 検索結果からレシピを選択 | 選択した製品のBOMを表示し、リストには自動登録されない |
| T-014 | 選択中製品の数量を有効値に変更 | 保存ボタンなしでBOM数量が再計算される |
| T-015 | 登録済み製品の数量を変更 | 対象登録と集計値へ即時反映され、他製品には影響しない |
| T-016 | 製作リストへ製品を追加・削除 | フロントエンド状態と素材集計が更新され、バックエンドへの保存リクエストは発生しない |
| T-017 | 製作リスト・数量・選択レシピを変更した後にページを再読み込み | 同じブラウザで利用者の操作状態を復元し、BOMと素材集計を再計算 |
| T-018 | 製作リストを設定してブラウザ・タブを閉じ、同じブラウザで再度アクセス | 製作リストと現在の選択状態が復元される。バックエンドにユーザー状態の保存は発生しない |
| T-019 | 別端末・別ブラウザからアクセス | 製作リストの自動同期は行わない |
| T-020 | 2製品を登録し「すべて削除」を選択して確認ダイアログでキャンセル | 製作リスト、集計、ブラウザ保存分は変更されない |
| T-021 | 2製品を登録し「すべて削除」を確認して実行 | 登録製品・付随する数量とレシピ選択・集計が消去され、再読み込み後も復活しない |

これらは受け入れ条件であり、テスト実行済みという意味ではない。
